原木社区 PC 首页｜落地页文案与视觉设计方案
版本：2026-10-13
范围：设计提案。未修改首页业务代码。

一、推荐方向：方块世界里的文学栖息地

保留现有“方块跃然纸上，故事在此生长”的主标题、方块森林场景、Android 下载入口与开源共建内容。
补足访客最关心的三个问题：这里有什么好故事？我能怎样开始创作？这里的人在聊什么？
以阅读为首要入口，创作为次要入口，社区为轻量探索入口。移动端下载在访客了解内容之后出现。
整体叙事：认同兴趣 → 看见内容 → 想参与创作与交流 → 选择使用方式 → 了解共建理念 → 开始体验。

二、现有内容的调整

1. 保留首屏标题与 HomeVoxelWorld，收拢首屏颜色体系；使用刚完成的橙色木构字标。
2. 副标题中的“首个”暂改为定位陈述，避免依赖尚未提供依据的比较性宣传。
3. 现有 homeFeatures 中的读、写、交流文案可转化为首屏下方的三项简短入口；不再重复堆叠大型功能卡。
4. 下载模块保留现有版本与下载地址获取逻辑，视觉改为阅读场景与真实客户端截图配合。
5. 2024 年开源公开信保留为历史内容，另设“阅读开源公开信”入口。落地页展示当前适用的共建邀请。
6. “运营两年多”“200 位用户”“周活跃 81 人”等历史陈述不直接沿用为当前宣传。
7. 现有页面写 Mozilla 公共许可证，而仓库根 LICENSE 为 GNU GPL v3。发布前需统一开源表述；本轮文案不写具体许可证名称，也不延用“全部技术资产”的笼统承诺。

三、逐区块正式文案与排版

01｜导航
左侧：新版原木社区 Logo。
主导航：阅读 / 创作 / 社区。
辅助入口：下载 / 开源；登录与用户头像沿用现有账户状态。
主导航进入产品对应页面；下载和开源定位到首页相应区块。
不再同时堆叠多个高强调的注册或下载按钮。

02｜首屏
眉题：给热爱 Minecraft，也热爱故事的你
主标题：方块跃然纸上，故事在此生长。
定位：一个属于 Minecraft 同好们的文学社区。
正文：读一段未曾经历的冒险，写下属于你的方块故事。在这里，让想象有去处，让热爱有回声。
主按钮：发现好故事 → /read
次按钮：写下我的故事 → /write
轻入口：也可以先来社区逛逛 → /community
视觉：左文右图，约 46:54；沿用现有阅读、写作与交流的方块世界。标题两行，不将全段正文设置为像素字。
可选场景题注：从一块原木，到一个故事。

03｜三条参与路径（窄条）
读，去往新的世界。／小说、漫画与世界设定
写，让灵感落地。／从一个念头，到自己的作品
聊，遇见你的同好。／分享故事，也交换想法
对应 /read、/write、/community。使用三列简短文字，不再铺三张大面积彩色功能卡。

04｜精选作品：新增，放在下载区之前
眉题：在文字里，探索世界
标题：先读一段，再决定去哪里。
正文：熟悉的方块世界里，还有许多未曾见过的故事。
更多入口：逛逛完整书库 → /read
内容：首批展示 4 部真实公开作品，包含封面、书名、作者、类型与一句简介；作品点击进入各自真实详情页。
编排：优先人工精选，兼顾题材与封面差异；不把“精选”与未经定义的“热门”混用。
简介以作品原有内容为依据，不虚构获奖、读者数、评分或推荐语。
视觉：2:3 书封、统一展示框、自然留白。4 列宽屏，2 列窄屏，不自动轮播。
无可用作品数据时：收起作品卡，保留标题、说明与书库入口；不展示示例书名或空白骨架作为最终状态。
提案中的《主世界来信》《越过雪线》《红石余温》《群山之间》均为排版示例，不是真实作品。

05｜创作体验：新增
眉题：把你的想象，写成下一章
标题：那个一直想讲的故事，就从这里开始。
正文：一次冒险、一个角色，或一个尚未成形的念头。先把它写下来，再慢慢长成自己的作品。
三个支点：
  为作品起名，写下它的第一段介绍。
  把故事分成章节，一点点继续。
  让作品与读者相遇，听见他们的想法。
按钮：进入创作空间 → /write，沿用现有登录流程。
视觉：浅苔绿底，左侧文案，右侧真实写作界面裁片。选择一个真实、可展示的作品，保留章节目录和正文的结构。
提案的“记下灵感 / 写成章节 / 介绍作品”用于讲解创作过程，并非承诺产品拥有同名功能标签；最终截图须与实际 UI 一致。
不宣称尚未验证的自动同步、永久保存、收入保障或无门槛即时发布。

06｜社区交流：新增
眉题：故事之外，也有人在等你
标题：你的奇思妙想，值得被认真回应。
正文：聊聊喜欢的角色，交换世界设定，分享今天突然冒出的灵感。关于 Minecraft 与故事，这里有更多话题可以继续。
按钮：去社区聊聊 → /community
内容：展示 2—3 条真实公开讨论；保留帖子标题、圈子、摘要和可确认的时间，不使用虚构头像、回复数或用户证言。
视觉：左文右列表，以有内容的讨论体现社区氛围。避免大量头像堆叠和未经核实的“正在热聊”状态。
若帖子不足，以三个“可以聊什么”的静态方向替代：聊剧情、交换设定、分享灵感。明确它们是参与建议而不是现有帖子。

07｜Android 下载：优化现有模块
眉题：让好故事，陪你走远一点
标题：离开电脑，也别离开那个故事。
正文：把原木社区装进口袋。在通勤途中、休息片刻，打开手机，继续探索你喜欢的方块世界。
按钮：下载 Android 版；版本号来自现有接口。
辅助文案：网页端也可以阅读。
视觉：暖纸色整块背景，一张当前版本真实阅读截图；可提供指向官方下载落地地址的二维码，地址验证后再生成。
下载地址未取到时：显示“下载信息暂时不可用”，保留“先在网页阅读” → /read，不放无法使用的下载按钮。
沿用微信内提示，不新增未经验证的 iOS 入口，不承诺跨端阅读进度同步。

08｜开源共建：压缩现有公开信
眉题：OpenLoghome · 开源共建
标题：社区的下一章，也可以由你来写。
正文：原木社区由 OpenLoghome 开源项目驱动。提交一个问题、补充一份文档、贡献一段代码，或把这里介绍给一位朋友，都是参与建设的方式。
主链接：前往 GitHub → https://github.com/OpenLogHome
辅助入口：阅读开源公开信 → 新建历史文章位置，保留 2024-03-01 的原始发布日期。
参与方式：贡献代码与文档 / 反馈问题与想法 / 把原木介绍给朋友。
收尾句：一个因热爱而生，也由热爱继续建设的地方。
视觉：纸白底、细分隔线、简洁文字布局。原来的开源、协作、GitHub、聊天四张大插画不再逐屏堆叠。
QQ群号与入群链接核实有效后放入共建详情或页脚。

09｜常见问题：新增，可折叠
问：这里可以读到什么？
答：原木社区面向 Minecraft 及其衍生文化爱好者。你可以在书库里发现小说、漫画与世界设定。
问：从哪里开始创作？
答：从「创作」进入个人创作空间，创建作品，再添加章节。需要登录时，按页面提示完成即可。
问：一定要下载客户端吗？
答：不必。你可以通过网页端阅读、创作和参与社区，也可以选择 Android 客户端。
问：不会写代码，也能参与共建吗？
答：当然。反馈使用中的问题、补充文档，或向同好介绍原木社区，都是参与的方式。

10｜底部行动区
标题：下一段冒险，从这里翻开。
正文：先读一个故事，也许下一个故事就来自你。
主按钮：发现好故事 → /read
次入口：我也想写 → /write
页脚：保留现有必要的平台信息、协议与反馈入口。

四、视觉规范

主题：纸张的安静 + 木材的温度 + 方块世界的想象力。
品牌橙：沿用新版 Logo 的现有颜色；主要留给 Logo 与少量识别性点缀。
木棕 #79573C：主要行动按钮、重点链接。
森林深色 #333B2F：标题和正文。
苔绿 #52643E：主题强调与少量辅助图形。
纸白 #FAF8F3：主背景；面板 #FFFDF8。
浅苔绿 #ECF0E4：创作与收尾区块。
暖纸色 #F3EEE5：下载区；分隔线 #E3E4D9；次要文字 #6D7365。
不让橙、棕、绿同时争夺按钮主色。较浅颜色仅用于背景，文字需验证实际对比度。

桌面基准：1440px 画板、1200px 内容宽度；导航约 72px 高，首屏约 600—680px。
字号建议：首屏 52—56px，区块标题 30—36px，正文 16px，辅助文案 13—14px；正文行高 1.7—1.9。
字体：正文与标题沿用系统中文无衬线。木构字形只用于 Logo。示例书封或引文可少量使用宋体增加阅读感。
间距：区块上下 80—96px，内容列间 32—48px；标题与正文 16px；正文与按钮 24—28px。
按钮：约 44—48px 高，圆角 6—8px；内容展示面板圆角 10—12px；书封圆角 3—4px。
层次：首屏插画与内容展示承担视觉焦点；减少大阴影和无意义描边，不让每段内容都装进大卡片。
动效：保留现有方块场景的轻交互。按钮、书封以轻微位移或底色变化反馈；不新增自动轮播和连续数字动画。
宽屏：首屏左右布局；作品四列；创作、社区、下载交错布局。
窄屏：文案先于插图；作品两列；其他区块单列。按钮保持足够点击面积；避免挤压文字来维持桌面排版。
提案视觉跟随查看环境显示明暗配色；正式首页优先实现与现有站点一致的浅色版本，深色版本可后续单独校验。

五、素材与实现交接

可复用：新 logo_new.png、HomeVoxelWorld、既有 Android 下载接口、/read 与 /write 与 /community 路由。
需要准备：4 部真实精选作品及封面、1 张当前写作界面截图、1 张当前 Android 阅读界面截图、2—3 条公开讨论。
需要核实：Android 下载目标、开源声明、QQ群入口、历史公开信的归档位置。
需要新增：首页精选内容配置、历史公开信详情入口、必要的内容失败回退。
写作截图和阅读截图应使用可公开的示例内容，避免出现私人草稿、私人消息或账户敏感信息。
正式落地页建议 title：原木社区 - Minecraft 同人文学与创作社区
建议 description：在原木社区发现 Minecraft 同人小说、漫画与世界设定，写下自己的方块故事，与同好交流灵感。支持网页阅读与创作，并提供 Android 客户端。

实施顺序：
  第一批：重排页面、接入真实精选作品、补创作与社区区块、压缩公开信、统一色彩与按钮。
  第二批：替换精修截图、补历史文章入口、完善下载失败状态和窄屏表现。
验收重点：所有入口指向真实页面；不存在示例内容混入正式数据；下载失败仍可继续浏览；静态文本在场景未加载时可见；减少动态效果偏好受到尊重。

loghome-pc-frontend/pages/index.vue：现有首屏、下载、公开信与 homeFeatures。

loghome-pc-frontend/pages/read/index.vue：小说、漫画、世界设定与推荐列表。
loghome-pc-frontend/pages/write/new.vue：创建文字或漫画作品。
loghome-pc-frontend/pages/write/index.vue：作品管理与草稿箱。
loghome-pc-frontend/pages/community/index.vue：圈子与公开帖子。
loghome-pc-frontend/pages/novel/_id.vue：书架与读者评论。
LICENSE：仓库当前开源许可证文件。

附注：聊天中的交互布局仅用于评审。其导航和按钮以页内跳转演示区块，正式按钮去向以本方案为准。书封、帖子话题、写作文字、手机界面及森林书本构图均有示意性质；首屏正式实现保留项目既有 HomeVoxelWorld。
