# 原木 MiniMinecraft

从 `Minecraft多人联机_-_灵光闪应用_20261010_170137_148167` 导出应用迁移的独立 H5 游戏。保留游戏画面、世界生成、背包、模组编辑、Minecraft Java 1.21 材质包及原存档管理界面；存档改为按原木账号保存在本应用的独立 Node 服务。

原目录保持原样。`vendor/game.bundle.js` 是导出的 React/Three.js 构建产物，没有原始 React 工程；构建时通过 `scripts/build.cjs` 在明确的函数边界替换存储层，生成 `dist/`，不直接修改原始 bundle。替换边界不匹配会中止构建。`public/` 保存导出的本地素材与材质包。

## 本地运行

需要 Node.js 22.13 或更高版本；无第三方运行依赖，无需 MySQL。

```sh
cd loghome-miniapps/log-miniminecraft
npm ci
npm test
npm run dev
```

首次使用时默认目标帧率为 60 FPS、视距为 32、区块加载速度为最大档（每批 10 个区块）。用户已保存的有效设置继续优先，不会在更新后被覆盖。

默认地址为 `http://127.0.0.1:8788/log-miniminecraft/`，调试默认连接原木后端 `http://127.0.0.1:9000`。可创建不入库的 `.env.development`：

```dotenv
PORT=8788
HOST=127.0.0.1
LOGHOME_API_URL=https://api.loghome.ink
DATA_DIR=./data/players
ALLOWED_PARENT_ORIGINS=null,http://localhost:8080,http://127.0.0.1:8080
```

票据签发与兑换必须连接同一个原木后端。开发环境也必须用真实原木账号；直接打开页面只会提示从原木入口进入，不提供游客账号或鉴权绕过。源码或素材变化后重新执行 `npm run build`。

## 生产部署

复制 `.env.example` 为 `.env`，配置真实原木后端、可信父来源及可写的 `DATA_DIR`；数据目录不放在静态资源目录中。构建后运行：

```sh
npm ci
npm run build
npm start
```

`npm start` 现在会先自动构建；服务启动时还会检查首页、启动脚本、样式及游戏模块是否存在且非空。不要把 `public/` 当作完整发布目录：游戏模块由 `vendor/game.bundle.js` 经过构建生成，只有完整 `dist/` 可以提供前端服务。使用 systemd/PM2 直接执行 `server/index.cjs` 时，需要先在发布目录执行 `npm run build`，再重启服务；缺少必要文件会拒绝启动。

Windows 检出同样受支持：构建在应用源码补丁前统一 CRLF/LF 换行，项目 `.gitattributes` 也将 JS/CJS 源码指定为 LF。源码补丁全部完成后才替换 `dist/`，因此补丁匹配失败不会先删除已有发布文件。

首屏提供无需图片资源的 Loading 界面，按连接社区、账号验证、存档同步、游戏程序加载、原版材质准备、菜单挂载六个真实阶段更新进度。阶段进度不代表下载字节百分比；网络等待期间保留当前阶段。菜单挂载并经过两帧绘制后关闭遮罩；启动失败显示原因，界面准备超时也会结束等待并提示重新加载。APP 容器支持可选的 `loading` 阶段消息，收到后显示小程序自己的 Loading，避免通用提示遮挡；其他小程序保持原有行为。已有 APP 包需要更新容器页面，才会让出通用提示。

部署并重启后检查公网资源：

```sh
npm run check:deployment -- https://miniapps.loghome.ink/log-miniminecraft/
```

该检查同时验证各启动文件的 HTTP 状态及响应类型，能够发现游戏模块 404 和反向代理把 JavaScript 请求回退到 HTML 的情况。APP 显示 `Failed to fetch dynamically imported module` 时，应先检查报错中的脚本 URL；若返回 404，需要重新构建并发布完整目录，单纯刷新 APP 无法恢复缺失文件。

前端与 API 同源，由同一独立服务提供。建议使用进程管理器或 systemd 保持服务运行。HTTPS 反向代理示例：

```nginx
location /log-miniminecraft/ {
    proxy_pass http://127.0.0.1:8788;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    client_max_body_size 52m;
    proxy_read_timeout 90s;
}
```

如果使用该代理并确保其覆盖 `X-Real-IP`，可设置 `TRUST_PROXY=1`；直接监听公网时保留 `0`。不要为此路径配置禁止原木容器嵌入的 `X-Frame-Options: DENY/SAMEORIGIN`。默认 `BASE_PATH=/log-miniminecraft`；反向代理保留完整路径。

## 存档服务

- 游戏启动前兑换原木跨站票据，服务通过 `/users/token_by_cross_site` 和 `/users/userprofile` 校验真实账号；主应用长期登录 token 不传给游戏。
- 存档按鉴权账号隔离，客户端不能指定其他账号 ID。会话有效期为 12 小时；票据只能兑换一次。
- 保存世界的种子、改动方块、玩家位置和朝向、飞行状态、背包、容器/熔炉/门状态、模式、材质选择、模组、回收站等。TypedArray 和 Blob 使用带类型标签的 base64 编码，加载时还原。
- 存档列表从实际世界记录生成，避免保存正文和列表两次写入导致不一致。移入回收站、恢复存档分别一次提交完成。
- 游戏内返回主菜单会等待云保存；游戏运行中每 60 秒保存一次，切后台和原木容器关闭前也尝试保存。保存成功意味着服务已经完成落盘；关闭期间保存失败会通知容器 `close-failed`。直接强制杀进程可能丢失最近一次未完成保存的改动。
- 每次提交带 `revision`，不同窗口修改同一账号时后提交的旧版本得到 `409`，不会自动覆盖。此时重新打开游戏读取最新存档。
- 服务通过账号锁、临时文件、fsync 和原子 rename 落盘。每次成功写入保留上一个版本的 `.bak`，默认单账号快照上限 50 MiB，可通过 `MAX_SAVE_BYTES` 调整。
- 单机单进程运行，不要让多个 Node 进程同时写同一个数据目录。扩容到多副本前需要改用具备事务的共享数据库。

| 接口（前缀 `/log-miniminecraft`） | 用途 |
| --- | --- |
| `GET /api/health` | 健康检查 |
| `GET /api/config` | 父来源列表和容量配置 |
| `POST /api/session` | `{crossSiteToken}` 换取游戏 Bearer 会话 |
| `GET /api/snapshot` | 读取自己的 `{revision, updatedAt, state}` |
| `PUT /api/snapshot` | 提交 `{revision, state}`，返回新版本 |

数据文件为 `DATA_DIR/<原木账号ID>.json` 和 `.json.bak`。定期备份整个目录；恢复前停止服务，将目标备份恢复为对应 `.json` 后再启动，不要在运行中直接编辑。

旧导出应用的浏览器 IndexedDB/localStorage 数据不会自动混入当前原木账号；可使用原游戏存档管理的导出/导入入口迁移已有世界。设备上的画面和按键偏好仍留在浏览器 localStorage，世界进度以独立服务为准。

## 范围与验证

本服务实现游戏私有存档，不实现灵光平台的公共资源中心、社区分享审核、AI 生成接口，也不新增实时多人联机服务器。相关界面保留，未接入的写入/生成操作会明确提示，原木账号资料适配为当前玩家资料。不能将这部分能力视为已经迁移。

自动测试覆盖账号隔离、匿名访问拒绝、票据重放、并发冲突、落盘重读、上一版本备份、路径越界、TypedArray/Blob 往返、回收站原子操作以及打包存储适配。浏览器实测创建世界、进入三维游戏、保存返回、重新打开读取云存档。正式上线前还需通过真实原木容器验证票据兑换，并在安卓真机验证 WebGL、横屏、指针锁和后台关闭。

## 第一轮渲染性能优化

`scripts/performance-patches.cjs` 在构建时应用性能补丁，保持原始 vendor 导出文件不变；关键源码边界不匹配时构建失败。

- 同一水平区块的 21 个垂直子区块共享高度、温度和群系查询结果，保留原有噪声、洞穴、树木及方块生成顺序。
- 地形与火把/门/方块掉落物实例按属性维护 GPU 更新范围，合并相邻区间；超过 32 个区间时合并为覆盖范围，避免过多驱动调用。门动画不重复上传未变化的纹理，熔炉纹理变化不上传矩阵。保留尚未被渲染器消费的更新范围。
- 释放活动容器的克隆几何体、地形材质及共享实例深度材质；材质重新加载时释放旧材质；运行帧中每秒检查一次 30 秒容器缓存过期，移除退出时重复释放 RenderManager 的调用。

`test/performance.test.cjs` 对原版与补丁后的真实地图生成函数进行逐字节对比（3 个种子、12 个区块位置、252 个垂直子区块），并覆盖离散 GPU 更新、门动画、熔炉、清零后复用和资源回收。测试使用 Node VM 与缓冲/资源替身，不代表完成 WebGL 真机画面对比或帧率基准；仍需在真实容器中验证连续建造、探索和反复进入世界时的画面与帧耗时。

## 第二轮地图与 Worker 优化

`scripts/map-performance-patches.cjs` 由第一轮性能补丁调用，在两个 Worker 内分别注入辅助函数：

- 地形及跨区块树叶生成完成后，全空气子区块改用轻量标记和每个 Worker 一份的共享零数组，跳过面片、火把和门的整层扫描。保留子区块存在信息，避免改变水侧面/底面的原有判断。首次编辑按需分配，移除最后一个方块后恢复空标记；存档改动也走同一写入路径。生成期间仍有临时数组，本轮主要减少常驻数组与后续扫描。
- 初次区块同步对空子区块只发送标记；非空完整数据仍按原协议复制，因为加载 Worker 后续仍需读取它。
- GameWorker 返回邻接剔除数据时，仅打包四侧边界（每个非空子区块 1,024 字节，原为 4,096 字节），用 Transferable 转移新建的边界数组。缓存直接读取边界，不重建完整数组；不转移碰撞/编辑所需的原始地图数组。四侧都保留，支持缓存从不同方向复用。
- 初次剔除的两条结果发送路径补齐纹理索引数组的 Transferable。

新增测试覆盖完整 Worker 代码编译、空气标记写时分配、存档修改、负坐标边界编辑、最后一个方块清除、初始同步、真实 ArrayBuffer 转移，以及包含水/树叶的完整邻接数据与边界数据面片逐项一致。现有 252 个子区块的生成一致性样本中，146 个为空，省去这些子区块各自的 4 KiB 常驻数组（每个 Worker 仍保留一个 4 KiB 零数组）。这些结果不是设备 FPS 或进程总内存基准。

## 目标帧率

暂停菜单可选择 30、60、90、120 FPS，默认 60，本机通过 `log_minecraft_target_fps` 保存偏好。主画面与手持物按 RAF 时间戳和目标周期调度，替换原先约 33ms 的兜底刷新及空闲旁路；区块变化也遵守目标帧率上限。暂停恢复和切换档位重置调度，不补绘积压帧。输入、物理、拾取射线及水面反射的原有更新频率保持不变。实际 FPS 受屏幕刷新率和设备性能限制，右上角显示实际主画面渲染帧率。

`test/frame-rate.test.cjs` 验证多种屏幕刷新率下的四档调度、暂停恢复、长时间卡顿、切换目标和设置持久化；尚未以高刷新率真机验证实际 GPU 帧耗时。

## 第一轮画质改进

`scripts/visual-quality.cjs` 在现有补丁之后应用：

- 主场景 WebGL2 上下文请求原生 MSAA，平滑几何轮廓；实际支持和采样数由浏览器决定。
- 数组纹理保留最近邻放大和 sRGB，默认使用 `NearestMipmapLinearFilter` 平滑远处 mip 层级过渡；材质图片缩放禁用 Canvas 平滑，保留像素边缘。
- 合并面片的重复 UV 使用未取 `fract` 的梯度进行 `textureGrad` 采样，避免纹理重复边界产生错误的 mip 层级。
- 维持 2048 阴影图和原覆盖范围，让主方向光阴影跟随玩家相机，并在光空间按纹素对齐；主画面和反射通道使用同一个玩家相机作为锚点。降低深度/法线偏移以减轻阴影悬浮，并保留日夜更新时的目标高度。
- 修复数组纹理深度材质中与当前 Three.js 不兼容的 alpha 裁切宏，并给后续创建的所有地形容器正确绑定数组纹理深度材质。
- 当前 Three.js 对最近邻放大不启用各向异性过滤，因此不把此路径报告为硬件最大各向异性，也不对纹理层索引数据启用该过滤。

测试覆盖光空间对齐、远离原点/高处/垂直光照、alpha 裁切着色器生成和采样配置。另外使用项目自带 Three.js/材质在本机 Edge 无头 WebGL2 测试场景中验证了 9 个着色器程序，无编译错误或 WebGL 错误，MSAA 上下文已启用。该场景不是实际存档；实际地图外观、90 FPS 余量及安卓设备表现仍需实测。

## 第二轮画质改进（3–5）

暂停菜单新增「画质增强」：环境遮蔽 AO、天空与光照、水面与浅水过渡。三项默认开启，可独立即时切换，偏好存于本机 `log_minecraft_quality`。构建补丁为 `scripts/quality-effects.cjs`，运行时代码为 `scripts/quality-effects-runtime.js`；vendor 和地图数据格式不变。

- **AO**：采用 8 邻域深度采样的屏幕空间环境遮蔽，最大压暗 32%，对接触面和墙角增加层次。保留贪心网格，无需增加面片或 Worker 数据。它只能感知屏幕内可见深度，并非逐体素烘焙 AO；画面边缘、被遮挡物体或细小物体上的效果存在局限。
- **天空与光照**：每个 RAF 的主画面、反射和深度通道只推进一次环境更新；先恢复昼夜光照，再叠加天气。夜间保留最低环境光，地面反射光使用偏暖配色，雾与天空地平线配色保持一致。天气颜色克隆后插值，避免修改共享预设或产生随帧率变化的累计插值。固定昼夜时间时天空仍跟随玩家。
- **水面**：反射随观察角度变化，俯视时更多显示水下颜色，掠射角增强反射；用额外的不含水面场景深度估算水层厚度，浅水更透明、深水略深。深度为视线方向厚度，不是完整体积水模拟；保留方块水面和既有反射更新频率。修复关闭阴影时水面依赖未定义 `worldPosition` 的问题。
- **成本与释放**：AO 增加离屏目标和全屏通道；水面增强在存在可见水容器时增加一次场景绘制。主目标保留最多 4 倍 MSAA，深度预绘不启用 MSAA；窗口变化时调整目标尺寸，退出世界时释放。两项关闭时直接走原主画面渲染。离屏使用线性色彩，最终通道做输出转换，避免全画面变暗。

验证：`npm test` 共 34 项通过。另有独立浏览器检查 `test/quality-webgl.cjs`，需外部安装 Playwright（不加入游戏运行依赖），通过 `NODE_PATH` 指向该安装的 node_modules 后运行。`QUALITY_BROWSER` 可指定 Chromium/Edge 可执行文件，`QUALITY_SCREENSHOT` 可选指定截图路径。检查实际 WebGL 编译、四种 AO/水面开关组合、开关前后像素变化、天空颜色保持、六种时间/天气组合、阴影关闭、尺寸变化和管线释放。该检查使用合成场景，不代表实际存档或 Android 的画质与帧率；尤其水面增加绘制，不能保证继续保持 90 FPS，可通过独立开关对比。

天空接缝修复：`scripts/sky-quality.cjs` 将云层从经纬度 + `fract` 的非周期二维噪声改为方向空间三维噪声，消除经线跳变和顶部极点汇聚；天空方向改用球体局部坐标，避免玩家世界位置影响天空。补齐天空材质的输出色彩转换。浏览器检查新增开启云层时仰视极点及平移至 `(4096,180,-4096)` 的画面对比，验证天空不随世界原点变化；可用 `SKY_SCREENSHOT` 保存仰视检查图。

## 高阶光影第一版（阶段 1＋2）

暂停菜单 → 画质增强 → **高阶光影 · 第一版**。默认关闭，支持均衡/高两档及独立 Bloom 开关，偏好保存在 `log_minecraft_advanced_shader`。开启后统一启用环境配色、AO 和水面；普通模式的三个偏好不被覆盖，关闭后恢复。暂停期间的更改在恢复场景绘制后应用。

实现集中于 `scripts/advanced-shader-runtime.js`，由质量管线接入：

- HDR 最终输出使用 ACES 色调映射及固定曝光 1.1；暖阳光与偏冷天空环境光，手持物同步曝光和光照配色，UI 不参与后处理。
- 阴影采用可调半径 PCF：均衡 1.6、高 3，继续沿用稳定阴影范围。切换算法显式刷新材质程序，关闭后恢复算法与半径。这是柔化阴影版本，尚未加入 PCSS 接触硬化或级联阴影。
- AO 使用深度连续性选择邻居重建法线，避免跨轮廓差分；均衡 16、高 24 个螺旋分布样本，有限世界空间半径与压暗上限。无需历史缓冲，因此没有时间累积拖影；法线从深度重建，未增加独立法线 G-buffer。
- 水面法线随时间变化，反射坐标轻微扰动，使用现有无水场景颜色与深度做折射及分通道吸收；折射落到前景时回退原采样位置。复用已有水面预绘，不额外添加第三次全场景绘制，不改变方块几何或碰撞。
- Bloom 使用半分辨率 HDR 双通道可分离模糊、高光软阈值与低强度合成。关闭高级模式时释放专用目标、材质、几何；普通画质管线的共享资源留用并在退出世界时释放。
- 首次启用检查浮点渲染扩展及 HDR 帧缓冲，预编译场景与后处理程序。失败显示原因并回退普通模式。GPU 能力与像素开销仍依设备和分辨率变化，未承诺实际存档中 60/90 FPS。

验证：37 项 Node 测试通过。`test/quality-webgl.cjs` 使用项目真实 Three.js/材质，检查高级预设、连续三轮开关、关闭后像素完全恢复、纹理与几何数量不增长、HDR 不支持时回退以及既有画质检查；`ADVANCED_SCREENSHOT` 可保存高级模式检查图。`test/renderer-startup.cjs` 实际挂载游戏渲染组件，分别验证普通/高级模式启动、绘制、退出及再次进入；它使用内置方块注册与测试存储，并关闭区块加载，不代替完整存档的探索测试。两项浏览器脚本均通过外部 Playwright 运行，方法同上。

体积光、体积云、屏幕空间反射、彩色间接光属于后续阶段。本版建立独立可切换的高级模式及基础光影组合，尚非 Complementary 完整效果复刻。

## 高阶光影第二轮：水面、日光与大气

本轮覆盖高阶模式；普通模式设置与原合成路径保留。更新后刷新页面并开启高阶光影。

- **水面合成**：无水场景使用 HDR/MSAA 目标。先对地形处理 AO 与大气透视，再复制颜色/深度并仅绘制水面，最终统一 Bloom 与色调映射。水面把透射、吸收散射、菲涅尔反射及直射高光合成为最终辐射颜色，不再将已受光的倒影当作漫反射底色重复受光，也不再用透明混合再次叠底。AO 不再在水面之后乘到最终画面。新增颜色中间目标与全屏复制通道，但取消第二遍完整场景绘制，水面绘制阶段复用阴影。
- **日光与植被**：增强日光并根据太阳高度提供白天天空补光，不再统一削弱环境光；保留夜间差异。叶片材质添加有界背光透射近似，通过方块定义和纹理索引生成独立掩码；与玻璃/其他材质共用的纹理索引保守排除。材质库变化时更新掩码，退出高级模式释放。
- **大气与云层**：根据视线距离和平均高度渐进混合地平线颜色。处理主场景时绕过原材质雾，避免叠加两次；保留雾开关及天气/视距的近远边界，反射通道仍使用其原有雾。高级云层降低覆盖率，通过向太阳方向的额外密度采样表现云底和向阳边缘，仍为程序化天空云，不是体积云。

实现新增 `scripts/atmosphere-runtime.js`。验证共 38 项 Node 测试；WebGL 检查覆盖零灯光水下颜色透射、叶片材质编译、昼夜补光不累积、云层模式恢复、三轮开关后的普通画面逐像素恢复，以及 GPU 资源数量、能力回退、尺寸变化。游戏组件普通/高级模式启动与退出检查通过。检查使用合成场景和测试存储，实际山谷存档的曝光、水色、云量及 FPS 仍需实机对比。

### 晴天雾与水面波纹调整

- 晴天高度薄雾密度降至 `0.00065`，从 48 格后开始，混合上限为 22%；视距边界雾从至少 80% 视距处开始，使用水平距离，避免附近高山因高度被过早雾化。保留最终视距遮挡及浓雾天气的较早过渡。
- 水面移除沿坐标轴的周期正弦波，改为两层旋转、独立漂移的噪声梯度；反射、折射及高光共用同一波纹，并根据像素覆盖范围衰减远处细节。无需增加渲染通道。
- 39 项 Node 测试、WebGL 合成场景检查及普通/高级模式启动退出检查通过；实际存档的视觉效果仍需刷新页面后对比。

## 移动、手持动画与反射稳定性

`scripts/motion.cjs` 在构建时修复显示更新的时间尺度：手持物品使用经过时间及平滑的走路/奔跑权重，避免高 FPS 下重复读取同一份 Worker 状态时交替切换待机；人物步态按行走距离推进，身体转向按时间平滑。

显示位置使用 32 毫秒的 Worker 快照插值缓冲，相机、人物、手持光源和反射使用一致的显示位置；物理碰撞、交互防穿透及存档仍使用最新真实位置，不向未来预测。传送、长时间停顿及暂停后重置缓冲。水面反射在位置或视角变化时逐渲染帧更新，静止时保留 66 毫秒间隔；启用水反时移动中的 GPU 开销会相应增加。

52 项 Node 测试通过，覆盖 30/60/90/120 FPS 的动画一致性、60 Hz 快照到 120 FPS 的插值、暂停/传送重置及反射调度。真实渲染组件检查使用合成移动状态，验证普通/高级模式的平滑位置、主视角与反射视角一致及退出资源释放；WebGL 画质检查通过。实际存档中的移动观感及反射帧耗时仍需设备上体验。

## 原木贴图与树形

原版材质包版本提升至 2。引擎的有朝向方块以 `front/back` 为轴端，再旋转到世界方向；原木的年轮因此放在这两个槽位，其他四面放树皮。默认竖直树干的上下端显示年轮，四个侧面显示树皮，横放原木也沿相应轴显示端面。启动安装器自动更新已有原版材质包，保留世界与其他模组。

`scripts/trees.cjs` 统一正常加载、备用生成与跨区块重建的树形算法。沿用现有方块类型，采用接近原版普通树的分层轮廓：橡树高 4–6 格且树冠边角随机保留；云杉冠层向上收窄、交错伸展；金合欢有短分枝和扁平树冠，丛林树有较大树冠。高度与边角都由世界种子、树位置决定，不使用运行时随机数，因此不随加载顺序变化。跨区块扫描半径扩大至 3，覆盖全部冠层；生成时保护已有实心地形，树干优先于树叶。

更新后重新进入世界/重新加载区块会重建自然树形，存档中的玩家改动继续覆盖生成结果。验证覆盖跨正负区块与垂直子区块的一致性、树干连通、树形随机性、六向原木贴图、已有材质包升级及非植被地形保持。`test/trees-browser.cjs` 用真实游戏材质渲染种子树预览，可通过 `TREE_SCREENSHOT` 保存画面。

## 生物种群与自然生成

`scripts/population.cjs` 参考 [Minecraft 官方生成机制说明](https://learn.microsoft.com/en-us/minecraft/creator/documents/spawning/entityspawningdeepdive?view=minecraft-bedrock-stable)与 [Mojang 的牛生成规则](https://github.com/Mojang/bedrock-samples/blob/main/behavior_pack/spawn_rules/cow.json)，把原有的高频单只补刷改为种群、成群与环境规则共同控制。以下参数为本小程序的适配值。

- 自然动物与中立动物共用 10 只上限；为敌对类别预留独立 24 只预算。所有来源合计最多 64 只，手动生成也受总上限约束。自然生成还检查**实际目标区块**总数最多 6 只、同类数量遵循模组的 `maxPerChunk`，32 格邻域最多 8 只。手动生成可以超过自然种群/密度限额，但不能超过全局 64 只。
- 启动约 3 秒后首次尝试，随后每 20 秒最多尝试一群，通常 2–4 只，牛为 2–3 只；会受剩余容量和地形限制而少于目标数。实际使用物种 `spawnCooldown`，同一区块生成一群后冷却 60 秒，死亡或回收后也至少等待 20 秒再尝试。计时使用活动模拟时间，暂停或长卡顿不会积累补刷任务。
- 只在已加载区块、距玩家 24–96 格的范围内生成，较小视距会进一步限制范围。要求草地支撑、完整身体空间、没有其他生物重叠，并按群系筛选；狼可在森林、针叶林和雪地生成，支持雪地支撑。检查整个地表列，排除水面、石头屋顶和树叶顶；叶片遮盖会降低天空光。光照以主场景昼夜时间近似，不是完整体素光照传播，因此不模拟洞穴灯光/火把刷怪规则。默认高度范围覆盖到 320 格。
- 超过 96 格暂停 AI，超过 128 格、掉入虚空或所属区块卸载时回收，正确清理区块计数。渲染端同时清理网格、动画、配置与待加载队列，迟到的模型加载回调不会让已移除生物重新出现；正常回收不播放死亡粒子。

当前仍是活动区域的临时生物系统：世界存档尚不保存生物个体，不提供命名、驯养、繁殖或永久圈养。重新进入世界会重新建立种群；手动生成的生物也会随区块卸载回收。

验证：70 项 Node 测试通过，包括固定地表一小时模拟的数量上限、生成间隔、物种冷却、目标区块限额、昼夜/群系/地形、手动生成总限额及异步模型清理。`test/population-browser.cjs` 使用真实 GameWorker、消息通道和 EntityRenderer，模型 I/O 用延迟替身验证移除与回调竞争；另通过普通/高级画质渲染组件的启动、移动及退出检查。

## 水下画面与游泳

人物进入水体后使用浮力与阻尼，静止时约 65% 碰撞盒浸入水中，水面漂浮时眼睛露出水面；水平速度降低，支持疾游。空格／跳跃按钮按住上浮，Shift／下潜按钮按住下潜，放开后逐渐回到水面。手机上的潜行按钮在游泳期间改为按住下潜，松开停止；水中双击跳跃不会误切换飞行。靠岸时按上浮或开启自动跳跃可登上附近、头顶空间足够的岸边，保留实体碰撞。第三人称人物增加划水姿势，第一人称不再播放陆地走路晃动。

动物使用相同的水体体积采样和阻尼浮力，根据各自碰撞盒高度漂浮，每两秒尝试在 7 格内寻找可站立岸边并划水靠岸；没有岸时缓慢游动。离水后恢复原行为。GLTF 优先播放 swim 动画，缺少时用 walk 动作表现划水，几何模型使用已有 walk 动作。只把水判作游泳介质，岩浆不获得水的浮力。实现位于 `scripts/swimming.cjs`、`scripts/swimming-runtime.js`；泳姿状态经实际 Worker 消息传递，不改变存档格式。

`scripts/underwater-runtime.js` 按实际显示相机位置采样附近 3×3×3 方块，最多每 100ms 查询一次、同一时间最多一条未完成查询，因此第一／第三人称使用各自相机的浸水状态，而非固定海平面或人物脚部高度。水下增加随可见距离变化的红光吸收、蓝绿色散射和轻微边缘压暗，近处保持清晰，入水／出水平滑过渡；散射跟随昼夜光照。手持物同步轻微调色，UI 保持原色。

普通和高阶模式都支持水下效果，即使 AO／水面增强关闭也有效。复用现有深度、颜色目标和最终合成，水面背面显示无水场景的透射，不使用水上的镜面倒影；浸水时停止无效平面反射更新。普通模式在不支持浮点渲染目标的设备上使用字节颜色目标。原本关闭所有后处理时，入水仍需启用离屏与合成绘制，因此该场景会增加 GPU 开销。

验证包含 79 项 Node 测试（浮水、30/60/90/120 FPS、上浮下潜、空闲物理、碰撞／低顶棚／上岸、多种动物和相机采样），实际 GameWorker＋消息适配器检查、触摸下潜和普通／高阶渲染启动检查。WebGL 合成场景检查水面背面、水下像素变化、关闭增强后的水下显示与离水画面恢复，可用 `UNDERWATER_SCREENSHOT` 保存截图。尚需在实际存档和 Android 真机上体验水色、岸边细节和帧耗时。
