# 漫画第二阶段

已接入漫画作者工作台、话数编辑器、作品设置、读者详情页与阅读器。视觉采用浅灰底、白色圆角卡片、橙色主操作，并支持应用深色模式。

## 作者端

- 创作页漫画栏 → 话数管理；作品设置改为漫画专用设置页。
- 添加页面支持连续加入队列，文件按名称自然排序。显示传输进度和图片处理状态，可取消或失败重试。
- 失败重传保持文件顺序。替换失败不覆盖原页面；取消后迟到的响应不写入编辑内容。
- 页面可通过手柄拖动排序，网格保留逐页前移、后移和替换操作。页面 ID 在排序、删除时保持稳定。
- 整话预览直接读取本机编辑内容，无需发布，不写入阅读历史。
- 本机备份包含成功上传的页面；上传队列本身不跨刷新恢复。未完成的任务需重试或取消后保存。

## 读者端

- 双指缩放 1～4 倍、放大后拖动、双击放大或复位。缩放期间暂停滚动／翻页，可使用浮动复位按钮恢复。
- 支持上下滚动／左右翻页、左右阅读方向、页码滑块、白色／暖色／黑色背景、流畅／原图清晰度。本机保存阅读设置。
- 页漫加载当前页及相邻页；条漫保留页面高度，只加载视窗附近的图片。临近末尾预加载下一话首图。
- 无尺寸元数据的旧图片加载后会补充尺寸，位于视窗上方的尺寸变化会补偿滚动位置。
- 详情页提供封面、作者、简介、最近更新、可展开／倒序目录、收藏与同作者公开漫画；不展示虚构评分和下载按钮。

## 图片接口

继续使用鉴权接口 `POST /essays/upload_manga_page`。新客户端以 `Content-Type: application/octet-stream` 直接发送图片字节，通过 `?article_type=mangaStrip|mangaPage` 指定类型；旧客户端的 `{ img: dataUrl, article_type }` JSON 请求仍可使用。

后端生成原图、缩略图和阅读图后，以 `multipart/form-data` 文件字段 `img` 上传到图床 `/upload/img`，`apikey` 放在请求头中；不再将图片转为 Base64。与前端现有 `uni.uploadFile` / `el-upload` 协议一致。可通过后端 `mangaImageFileUploadUrl` 配置覆盖上传地址。

返回兼容原字段，并新增 `pages` 数组，每项含 `url, thumb, readingUrl, width, height`。编辑器按返回数组插入页面。服务端保存话数时保留这三个图片 URL。

- 漫画接口不再限制单张原图为 3.5 MiB，二进制及兼容 JSON 请求体上限均为 96 MiB；支持 JPEG、PNG、WebP、GIF。为避免解压炸弹，解码仍保留 3 亿像素的安全上限。反向代理及图床自身的容量限制需另行核对。
- 静态条漫超过 6000px 高度自动分段，逐段生成原尺寸图、最长 320×480 的缩略图及宽度不超过 1600px、高度不超过 16000px 的阅读图。
- 原尺寸资产和阅读图分离；GIF 保留动画，避免分段破坏动画。
- 处理 EXIF 方向。非分段原图保留上传字节，阅读图与缩略图使用正确方向。
- 客户端取消上传后，服务端中止未完成的存储请求及后续图片生成。
- 旧作品沿用原图片地址；缺少阅读图时自动回退原图，不会批量改写旧作品。
- 同作者公开作品接口过滤私密作品。

## 验证与调试

前端执行：

```sh
npm run test:manga
```

包含第一阶段权限、版本冲突、备份、进度回归，以及第二阶段手势、排序、队列取消重试、预览、图片分段／方向等测试。Sass 检查使用项目或已安装的 HBuilderX 编译器；没有 Sass 时该项明确跳过，需通过完整 UniApp 构建验证样式。

使用 HBuilderX 构建 H5。作者端页面验证使用只读接口测试数据；真实作品 398 已验证详情、续读、菜单和阅读设置。新图片处理代码需随后端进程重启或发布生效。

尚需在 iOS／Android 真机上验收双指触摸、WebView 手势边界和原生相册选择。浏览器双击及组件手势逻辑测试不代替真机验收。发现／评论／通知、离线缓存等属于后续阶段。
